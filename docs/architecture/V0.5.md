# V0.5 — Specialized Engineering Agents

V0.5 turns the V0.4 Level 6 developer into a governed specialist team without changing the execution authority model.

## Team

- Senior Backend Agent
- Senior Frontend Agent
- Senior Mobile Agent
- Database Agent
- DevOps/SRE Agent
- QA/Testing Agent
- independent Code Reviewer

Engineering Manager and Tech Lead remain responsible for business framing, architecture, decomposition, risk and cost. Specialists execute only tasks assigned by the approved plan.

## Deterministic routing

`AgentRouter` combines Tech Lead `owner_role`, approved file paths, Knowledge Engine stack evidence and task dependencies. Explicit roles are accepted only when compatible with the task domain. A generic `senior_developer` task may be inferred from paths/stack. Tasks spanning incompatible domains are returned to the Tech Lead for decomposition.

Canonical roles are `senior_backend`, `senior_frontend`, `senior_mobile`, `database`, `devops_sre` and `qa_testing`.

The router topologically orders dependencies. Unknown dependency IDs and cycles block execution; the LLM never invents an arbitrary order.

## Level 6 integration

`rea.level6.Level6Workflow` now points to `SpecializedLevel6Workflow`, which extends the V0.4 workflow. Existing V0.4 guarantees remain unchanged: isolated worktree, approved paths, Secret Guard, command policy, Docker sandbox, ASK approvals, non-bypassable cost gate and draft-PR-only publication.

Each specialist receives only its assigned task/files plus relevant upstream output. Specialist results are aggregated into the existing `CodingIteration` contract, preserving V0.4 artifacts and correction loops. Old work packages without technical tasks fall back to the V0.4 generic Senior Developer.

## QA gate

After validation succeeds and a real staged diff exists, QA/Testing runs before the independent Code Reviewer. QA compares acceptance criteria, assignments, diff and validation results. `request_changes` re-enters the bounded Developer correction loop. QA cost impact propagates to the existing human cost gate.

## Multi-repository boundary

The router understands a task-level `repository` field when present and exposes external repository assignments. V0.5 does not write across repositories inside a single workspace. Cross-repository execution is blocked until each repository can receive an isolated governed workspace.

## CLI

```bash
rea-agents capabilities
rea-agents route-plan .rea/work/issue-123-plan.json
```

`route-plan` is read-only and reports assignment order, specialist roles and external repositories.

## New audit events

- `specialist.handoff`
- `specialist.qa_gate`

## Invariants

1. Specialists never gain more execution authority than V0.4.
2. Routing cannot override policy, cost or Secret Guard gates.
3. A specialist can mutate only paths assigned to its task.
4. Incompatible role/file-domain combinations are blocked.
5. Dependency cycles are blocked.
6. QA may request changes before Code Review.
7. Cross-repository writes are never implicit.
