# REA V0.7 — Advanced Governance

V0.7 centralizes risk decisions before Level 6 execution.

## Flow

```text
GitHub Issue
    ↓
Engineering Manager
    ↓
Tech Lead
    ↓
Work Package
    ↓
Advanced Governance
    ├─ Security Agent
    ├─ Performance Agent
    ├─ Cloud Architect
    └─ FinOps Agent
    ↓
Deterministic Risk Engine
    ↓
LOW       → autonomous
MEDIUM    → governed
HIGH      → explicit Tech Lead approval
CRITICAL  → explicit human approval
COST      → human cost approval, always
PROD WRITE→ blocked
    ↓
Specialized Level 6
```

## Core rule

LLM specialists provide findings. They do not own the final decision.

The deterministic Risk Engine may accept specialist escalation but never allows a specialist
to reduce risk already detected from the Work Package.

Decision precedence is:

1. Production write/state change → `blocked`.
2. Any cost impact → `cost_approval`.
3. Critical risk or explicit specialist human escalation → `human_approval`.
4. High risk → `tech_lead_approval`.
5. Medium risk → `governed`.
6. Low risk → `autonomous`.

Cost approval is structurally separate from risk approval and cannot be bypassed by
`governance-human` or `governance-tech-lead`.

## Explicit approvals

The existing CLI `--approve-rule` flag carries two governance-only approval tokens:

```text
governance-tech-lead
governance-human
```

These tokens do not approve command-policy `COST_APPROVAL` decisions.

Examples:

```bash
rea issue run 42 \
  --repo owner/repo \
  --workspace ../repo \
  --approve-rule git-push \
  --approve-rule governance-tech-lead
```

Critical risk requires:

```text
--approve-rule governance-human
```

Production writes remain blocked even with both approval tokens.

## Standalone assessment

An existing Work Package can be inspected without executing Level 6:

```bash
rea governance assess .rea/work/issue-42-plan.json
```

The output includes score, risk level, decision, deterministic signals and each specialist
assessment.

## Audit events

V0.7 writes:

- `governance.specialist_assessed`
- `governance.assessed`
- `governance.gate_passed`
- `level6.governance_preflight`

The Level 6 workflow plans once, runs governance against that exact Work Package, and then
reuses the same package for implementation. This prevents governance/execution drift.
