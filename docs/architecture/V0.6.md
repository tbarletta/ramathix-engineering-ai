# V0.6 — Production/SRE Read-Only Diagnostics

## Goal

V0.6 adds production incident analysis while keeping production access at Level 1–2. REA may
read observability, source-control and diagnostic evidence, but it has no production write
interface.

## Access model

```text
Level 1
  logs / metrics / traces / exported observability signals

Level 2
  deployments / source changes / database snapshots / queue snapshots / infrastructure state

WRITE
  always denied
```

`ProductionReadPolicy` is separate from the development command policy. Production capabilities
are explicit and every `write=True` request raises `ProductionWriteDenied`.

## Workflow

```text
Incident
  |
  v
Read-only signal providers
  |
  +--> JSON/JSONL observability snapshots
  +--> governed Git history
  |
  v
Secret redaction
  |
  v
Evidence timeline
  |
  v
Incident/SRE Agent
  |
  +--> impact summary
  +--> timeline
  +--> root-cause hypotheses + confidence + evidence IDs
  +--> remediation proposals
  +--> preventive actions
  |
  v
Postmortem + operational artifact
```

## CLI

Inspect the effective production policy:

```bash
rea production policy
```

Inspect evidence without invoking the Incident Agent:

```bash
rea production inspect \
  --service payments \
  --signals ./snapshots/payments-logs.jsonl \
  --signals ./snapshots/payments-metrics.json \
  --git-repo ../payment-service
```

Analyze an incident:

```bash
rea incident analyze INC-2026-0042 \
  --service payments \
  --title "Payment API elevated 5xx" \
  --description "Errors started after the latest release" \
  --started-at 2026-08-21T18:00:00Z \
  --signals ./snapshots/payments-logs.jsonl \
  --signals ./snapshots/payments-metrics.json \
  --signals ./snapshots/deployments.json \
  --git-repo ../payment-service
```

At least one `--signals` snapshot or `--git-repo` is required.

## Evidence

Every production signal receives an `evidence_id`. The Incident/SRE Agent is not allowed to cite
an identifier that was not supplied to it. Unknown evidence references fail deterministic
validation.

Supported evidence kinds:

- log
- metric
- trace
- deployment
- git_change
- database
- queue
- infrastructure

Git evidence is collected with governed `git log` and `git show --name-only`; it does not mutate
the repository and still passes the central command policy.

## Safety invariants

1. V0.6 has no production mutation provider.
2. Any production policy authorization with `write=True` is denied.
3. Restart, scale, deploy, rollback, reprocess, cache clear, database mutation and queue mutation
   are remediation proposals only.
4. State-changing remediation text is deterministically marked `requires_write=True` even if the
   model forgets to mark it.
5. Cost-bearing remediation sets `cost_approval_required=True`; agents cannot approve cost.
6. Secrets are redacted before evidence is sent to the model or saved to incident artifacts.
7. Evidence precedes inference; a hypothesis must cite existing evidence IDs.
8. A root-cause hypothesis does not become a permanent fact automatically.
9. Git access is read-only and passes through the governed local runner.
10. No personal production credentials are part of the V0.6 interface.

## Provider strategy

V0.6 starts with JSON/JSONL snapshots plus local Git history. This allows the Incident Agent and the
read-only governance model to be evaluated before introducing live production connectors.

Future live adapters may include:

- Grafana / Prometheus
- CloudWatch
- Sentry
- OpenTelemetry backends
- Kubernetes read-only
- PostgreSQL read-only
- Redis read-only
- RabbitMQ read-only

Each future adapter must implement the same read-only provider protocol and be deployed with a
dedicated least-privilege credential. Adding a live connector must not create a write path.

## Artifacts

Incident analysis is written to:

```text
.rea/incidents/<incident-id>.json
.rea/incidents/<incident-id>.md
```

The Markdown postmortem contains:

- incident and service
- impact
- timeline
- root-cause hypotheses with confidence/evidence
- proposed remediation
- preventive actions

The JSON artifact preserves the structured evidence and analysis for future operational memory.

## Out of scope

- restart or scale
- deploy or rollback
- reprocessing
- cache mutation
- database write
- queue write
- infrastructure changes
- autonomous cost approval
- live credentials with write permissions
