# REA V1.1 — Autonomous Self-Evolution Control Plane

V1.1 closes the loop around the existing Level 6 Issue-to-PR executor. It does not grant an
LLM unrestricted authority. It adds evidence, experiments, deterministic evaluation and bounded
promotion so the system can improve safely.

## Closed loop

1. `AuditObserver` normalizes CI, review, iteration-limit, human-correction and production events.
2. `OpportunityDetector` requires repeated evidence before proposing a hypothesis.
3. `EvolutionWorkflow` creates a crash-safe experiment and delegates candidate construction to
   an isolated builder (normally the existing Level 6 worktree engine).
4. `EvaluationEngine` measures the same versioned benchmark on baseline and candidate.
5. Critical capability regressions veto a candidate even when its aggregate score increases.
6. `PromotionPolicy` permits automatic promotion only for low-risk, no-cost, non-protected
   changes. Changes to governance, policy, CI or the promotion controller require human review.
7. Every outcome becomes a durable lesson. The UCB1 optimizer may select a model/prompt candidate,
   but cannot change model weights or bypass evaluation.
8. `CanaryController` supports shadow validation, bounded canary and automatic rollback through
   an environment-specific adapter. Production promotion always requires an explicit token.

## Packages

| Module | Responsibility |
|---|---|
| `contracts.py` | Events, hypotheses, metrics, experiments, lessons and decisions |
| `discovery.py` | Observation and repeated-evidence opportunity detection |
| `evaluation.py` | Utility score, baseline comparison and regression vetoes |
| `store.py` | Atomic experiment persistence and append-only lessons |
| `workflow.py` | Budgeted, resumable experiment lifecycle and circuit breaker |
| `promotion.py` | Self-modification boundary, shadow/canary and rollback |
| `optimizer.py` | Benchmark-rewarded model/prompt routing |
| `cli.py` | Read-only discovery and lesson inspection |

## Adapter boundaries

The control plane deliberately uses protocols for candidate building, benchmark measurement,
PR publication and deployment. Real installations must connect these protocols to Level 6,
GitHub, their CI system and their deployment platform. This keeps credentials and production
semantics outside the generic core.

## Required repository controls

Before enabling auto-merge, configure GitHub branch protection with required CI, prohibit direct
pushes, require ownership review for protected paths, and pin Actions. The policy rejects
self-authorization in code, but server-side repository controls remain mandatory.

## CLI

```bash
rea-evolve discover --repo owner/repo --audit .rea/audit.jsonl
rea-evolve lessons --repo owner/repo
```

Discovery is read-only. Running an experiment requires configured implementations of the four
adapter protocols and is expected to be invoked by an event worker or the conversational
controller.
