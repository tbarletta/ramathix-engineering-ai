# V0.4 — Level 6 Autonomous Issue-to-PR

## Goal

V0.4 is the first Ramathix Engineering AI milestone that may mutate source code. The workflow
remains governed: the model proposes structured file mutations, deterministic components enforce
workspace, command, cost, secret and publication policies, and the final output is a draft PR.

## Workflow

```text
GitHub Issue
    |
    v
Knowledge refresh
    |
    v
Engineering Manager
    |
    v
Tech Lead -------- reject --> STOP
    |
    v
Publish preflight
    |
    v
Isolated git worktree
    |
    v
Senior Developer execution
    |
    +--> bounded file mutations
    |
    +--> governed validation commands in Docker
    |
    +--> test failure --> Developer correction
    |
    v
Stage + actual diff
    |
    v
Independent Code Reviewer
    |
    +--> request_changes --> Developer correction
    |
    v
Commit
    |
    v
Approved git push
    |
    v
Draft Pull Request
```

## CLI

```bash
rea issue run 123 \
  --repo tbarletta/social-media \
  --workspace ../social-media \
  --base master \
  --approve-rule git-push
```

`git-push` is an ASK policy. The command will not start autonomous implementation unless that rule
is explicitly approved for the invocation.

Dependency installation is separate:

```bash
rea issue run 123 \
  --repo tbarletta/social-media \
  --workspace ../social-media \
  --approve-rule git-push \
  --approve-rule dependency-install \
  --allow-network
```

Network remains disabled by default. Docker uses `--pull never`, so the selected sandbox image
must already exist locally. Use `--image` for a project-specific prebuilt image.

## Safety invariants

1. The base branch is never edited directly.
2. Every Issue uses a deterministic `rea/issue-<number>-<slug>` branch in an isolated worktree.
3. Only paths approved by the V0.3 technical plan may be mutated.
4. Absolute paths and `..` traversal are rejected.
5. Symlinks and sensitive paths such as `.env`, private keys and credential stores are rejected.
6. Source content is redacted before entering the coding prompt when it resembles a credential.
7. Generated hard-coded credential patterns are rejected before staging.
8. Commands are executed without a shell and only after deterministic policy evaluation.
9. `COST_APPROVAL` can never be satisfied by an agent or by an approved-rule flag.
10. `ASK` commands require an explicit rule approval on the CLI invocation.
11. Validation runs in Docker with networking disabled unless separately authorized.
12. Git push is checked before implementation begins.
13. The Code Reviewer receives the real staged diff and validation results.
14. Reviewer `request_changes` returns to the Developer.
15. Iterations are bounded; default 3, hard maximum 8.
16. The generated pull request is always draft.
17. Merge remains outside autonomous V0.4 scope.

## Workspace boundary

REA stores linked worktrees under `REA_WORKTREE_PATH` (default `.rea/worktrees`). A repository name
is added by the CLI so repositories with the same Issue number do not share a worktree directory.

A previous interrupted run may reuse its worktree only when the current branch matches the
expected deterministic Issue branch.

## Mutation protocol

The executing Senior Developer uses a structured output:

```json
{
  "summary": "Implement the approved change",
  "changes": [
    {
      "path": "src/example.py",
      "action": "modify",
      "content": "complete file contents"
    }
  ],
  "commands": ["pytest -q"],
  "cost_impact": false
}
```

`create` and `modify` require complete UTF-8 file contents. `delete` requires null content.
Atomic writes prevent partially-written files.

## Validation scope

V0.4 validation accepts commands from policy rules intended for tests/quality and, when explicitly
authorized, dependency installation. Git, cloud, deployment and arbitrary network commands are not
valid Developer validation commands even when another policy might otherwise permit them.

## Artifacts

Execution state is written to:

```text
.rea/work/issue-<number>-execution.json
```

The artifact contains iterations, validation results, diff metadata and reviewer decisions. File
contents and credentials are not written to the audit log.

## Exit behavior

- `0`: draft PR created
- `11`: explicit ASK approval required
- `20`: human cost approval required
- `30`: Tech Lead rejected the request
- `40`: deterministic safety/policy block
- `50`: implementation iteration limit exceeded

## Out of scope

- merge or auto-merge
- production writes
- production deploy
- infrastructure provisioning
- autonomous cost approval
- unrestricted shell
- unrestricted filesystem access
